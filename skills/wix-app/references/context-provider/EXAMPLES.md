## Complete Example

Scaffold each provider with `wix generate` first (see the [Quick Start Checklist](../CONTEXT_PROVIDER.md#quick-start-checklist)); the examples show the finished files.

### Counter with a goal-gated banner

From the request *"Create a counter that counts how many times a button was clicked and show a congratulations banner only when the count reaches 10. Use context providers and native components, do not create an editor react component."*

Every element here is a native Editor element, so every consumer is a binding-only consumer. `count >= 10` cannot be evaluated at the binding, and neither can its negation — so the provider resolves both sides itself and exposes one ready-to-bind boolean per gated element. See [Derived Values (Mandatory)](DERIVED_VALUES.md#derived-values-mandatory).

**`src/extensions/site/contexts/click-goal-context/click-goal-context.tsx`**:

```typescript
import React, { createContext, useContext, useState } from 'react';
import type { BooleanValue, NumberType, Text } from '@wix/editor-react-types';

export interface ClickGoalContextType {
  count: NumberType;
  isCongratsBannerHidden: BooleanValue;
  isProgressHintHidden: BooleanValue;
  statusMessage: Text;
  increment: () => void;
}

export interface ClickGoalProviderProps {
  children?: React.ReactNode;
  goal: NumberType;
}

const ClickGoalContext = createContext<ClickGoalContextType | null>(null);
ClickGoalContext.displayName = 'ClickGoalContext';

export function useClickGoalContext(): ClickGoalContextType {
  const context = useContext(ClickGoalContext);
  if (!context) {
    throw new Error('useClickGoalContext must be used within a ClickGoalContextProvider');
  }
  return context;
}

export function ClickGoalContextProvider({
  children,
  goal,
}: ClickGoalProviderProps): React.ReactNode {
  const [count, setCount] = useState<NumberType>(0);
  const target = goal ?? 10;

  const increment = (): void => {
    setCount((current) => current + 1);
  };

  // Derived at render time from the state — never stored in a second state value.
  const hasReachedGoal = count >= target;
  const remaining = target - count;
  const statusMessage = hasReachedGoal
    ? 'Goal reached'
    : `${remaining} more ${remaining === 1 ? 'click' : 'clicks'} to go`;

  const api: ClickGoalContextType = {
    count,
    isCongratsBannerHidden: !hasReachedGoal, // hidden until goal is reached
    isProgressHintHidden: hasReachedGoal, // the complement, precomputed
    statusMessage,
    increment,
  };

  return (
    <ClickGoalContext.Provider value={api}>{children}</ClickGoalContext.Provider>
  );
}

ClickGoalContextProvider.displayName = 'ClickGoalContextProvider';
export default ClickGoalContextProvider;
```

The site owner binds the Button's click handler to `increment`, the banner's `hidden` property to `isCongratsBannerHidden`, the hint's `hidden` property to `isProgressHintHidden`, and each text element's content to `count` or `statusMessage` — the platform converts both to rich text at the binding.

**No consumer component and no `contextDependencies` exist for this section** — the provider registration above is the entire implementation.

`useClickGoalContext` is still exported and `contextSpecifier.hook` still registered — those are manifest requirements, not a consumer wiring. That is the rule in [The Provider's Shape Never Shrinks](PROVIDER_PATTERN.md#the-providers-shape-never-shrinks): "native elements only" constrains which consumers get written, never the provider's shape.

Note also that every bindable item carries a `description` naming what to bind it to; see [The Manifest Is the Binding Contract](MANIFEST.md#the-manifest-is-the-binding-contract).
